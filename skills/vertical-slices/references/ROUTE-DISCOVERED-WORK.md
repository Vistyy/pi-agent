# Route Discovered Work

Apply the bounded supported result and Task dependency definitions from the main skill.

- Keep work inside the current Task when it is necessary to deliver its approved result, does not change accepted intent or its boundary, and leaves the accepted review path practical.
- Reassess the accepted review path as soon as the implementation shape becomes concrete, before continuing materially dependent work, before submitting a complete implementation for review, and after later work materially changes that shape.
- Compare the actual behavior groups, state relationships, interface changes, and verification arguments with the one coherent judgment stated by the accepted review path.
- Stop and present evidence when discovered work changes accepted intent, reveals another bounded supported result, or shows that a human can no longer review the complete result coherently through the accepted path.
- Treat multiple independently understandable behavior groups, state relationships, interface changes, or verification arguments as boundary evidence requiring a stop unless concrete evidence shows that they form the one bounded supported result stated by the accepted review path.
- Treat a disproven review path as a boundary concern even when all discovered work is necessary for the final result.
- File count, line count, effort, or verification count alone does not disprove a review path.
- Keep unrelated work outside the current Task.

Preserve completed work and leave the recovery decision to the applicable authority.
Obtain approval before changing an approved Task boundary.
After approval, update the authoritative Task record or graph before implementation continues.

Routing is complete when all required work belongs to an approved Task and the authoritative graph matches those boundaries.
